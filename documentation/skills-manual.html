Installation des skills

Les skills sont stockés dans .claude/skills/ à la racine du répertoire de travail. Chaque skill est un sous-répertoire contenant un fichier SKILL.md.

# Vérifier que les skills sont en place
ls /mnt/e/lamae-sota-tool/.claude/skills/
# sota-curate  sota-export  sota-new  sota-quality
# sota-review  sota-status  sota-update  sota-write
Invocation : dans Claude Code, tapez /sota-new "Votre sujet de recherche". La barre oblique déclenche le skill automatiquement.

3 — Variables d'environnement #envvars

À configurer avant de lancer /sota-new. Le strategist_agent effectue un pre-flight check et signale les clés manquantes.

VariableRequisUsage
ELSEVIER_API_KEYREQUISRequêtes ScienceDirect (étape 2)
ELSEVIER_INST_TOKENREQUISAccès full-text Elsevier (étape 2.5)
IEEE_API_KEYREQUISIEEE Xplore (étape 2)
UNPAYWALL_EMAILREQUISTéléchargement PDF Unpaywall (étape 2.5)
S2_API_KEYRECOMMANDÉ100M req/day Semantic Scholar (vs ~10 sans clé)
 
# Ajouter dans ~/.bashrc ou ~/.zshrc (ou exporter avant de lancer Claude Code)
export ELSEVIER_API_KEY="votre_cle"
export ELSEVIER_INST_TOKEN="votre_token"
export IEEE_API_KEY="votre_cle_ieee"
export UNPAYWALL_EMAIL="vous@institution.fr"
export S2_API_KEY="votre_cle_s2"  # optionnel
Important : déclarer les variables dans un fichier .env ne suffit pas — les agents ne le sourcent pas automatiquement. Utilisez export dans le shell parent de Claude Code.

4 — Référence des skills #skills

/sota-new
DÉMARRAGE CHECKPOINT A

Lance un nouveau run PRISMA complet : crée le répertoire de run, interroge les APIs, filtre les papiers jusqu'au checkpoint borderline.

/sota-new "ML for robust quantum control protocols"
# ou : /sota-new (sans argument → Claude demande le sujet)
Étapes automatisées
  • 1
    Crée runs/YYYY-MM-DD-slug/ depuis le template, remplit RUN.md
  • 2
    Exécute scoper_agent → strategist_agent (6 APIs) → pdf_retriever_agent (optionnel) → translator_agent
  • 3
    Exécute curator_agent phase 1, recompte les lignes ACCEPT du log (ne fait pas confiance au résumé)
  • 4
    S'arrête et présente les papiers borderline sous forme de tableau
Outputs produits
scoper_output.md raw_extraction_list.md strategist_output.md translation_report.md borderline_review.md pdf_retrieval_report.md
/sota-curate
APRÈS CHECKPOINT A

Résout le checkpoint borderline, finalise le corpus, exécute l'analyse (notebook Sections 1–6, csv, pdf_analyzer si PDFs disponibles).

# Répondre d'abord aux borderlines dans le chat :
# "INCLUDE P0012, EXCLUDE P0034, INCLUDE P0067"
/sota-curate
# ou : /sota-curate runs/2026-10-11-mon-sujet
Étapes automatisées
  • 1
    Lit borderline_review.md, applique les décisions du Conductor
  • 2
    Recompte les ACCEPT depuis le decision log (corrige le résumé si divergence)
  • 3
    Forke agent_analyst → master_research_data.csv + notebook Sections 1–6
  • 4
    Forke pdf_analyzer_agent (optionnel, si pdfs/ non vide)
Outputs produits
curation_report.md master_research_data.csv prisma_analysis_report.ipynb bridge_papers.json pdf_analysis_report.md
/sota-quality
CHECKPOINT B

Enrichit les citations OpenAlex, calcule le QualityScore (grade A–D), analyse les gaps et les limitations (TRL matrix), génère les 5 figures.

/sota-quality
Enrichissement obligatoire : si la majorité des citation_count est à 0, le skill requête OpenAlex pour les récupérer avant de calculer le score. Sans cette étape, S_network et S_bibliometric sont artificiellement bas.
Étapes automatisées
  • 1
    Enrichit les citations depuis OpenAlex → openalex_cache.json
  • 2
    Forke quality_agent → QualityScore 0–100, grade, bridge papers, recommandations
  • 3
    Checkpoint B : présente le dashboard + TRL summary. Attend PROCEED ou IMPROVE
  • 4
    Forke gap_finder_agent → gap_analysis.md
  • 5
    Forke limits_agent → limits_report.md (TRL matrix, Top 5 pistes)
  • 6
    Forke figure_agent → 5 figures exécutées dans le notebook
Outputs produits
quality_report.md openalex_cache.json gap_analysis.md limits_report.md figures_manifest.md fig1_taxonomy.svg fig2_timeline.png fig3_platform_heatmap.png fig4_concept_network.png fig5_gap_radar.png
/sota-write
CHECKPOINT C

Génère la bibliographie BibTeX, puis rédige le manuscrit complet (~8 000 mots) avec un checkpoint d'approbation du plan.

/sota-write
Structure du manuscrit produit
  • —
    Abstract ≤ 250 mots · Introduction (RQ1–RQ4) · Background · Méthodologie (PRISMA + QualityScore)
  • —
    Une section par cluster : bridge papers, Récents Progrès (24 derniers mois), synthèse intra-cluster
  • —
    Discussion · Future Directions (Top 5 de limits_report.md) · Limitations · Conclusion · Références
Outputs produits
references.bib synthesis_outline.md paper_draft.md
/sota-review
AUTO-ITÈRE

Revue adversariale du manuscrit : vérification de l'intégrité des citations, des comptages PRISMA, de la cohérence qualité/gaps/TRL. Itère jusqu'au verdict ACCEPT ou MINOR.

/sota-review
Checklist de la revue (vérifiée automatiquement)
  • Chaque citation présente dans le CSV et dans references.bib
  • Comptages PRISMA cohérents avec le decision log de curation
  • QualityScore et grade cités dans la Méthodologie
  • Bridge papers mentionnés dans les sections de cluster
  • Future Directions tracées vers les Top 5 de limits_report.md
  • N figures = N dans figures_manifest.md

Après verdict ACCEPT ou MINOR : lance automatiquement export_agent → .docx + .pptx.

Outputs produits
review_report.md paper_draft_vN.md (backup) paper_draft.docx slides_presentation.pptx
/sota-export
STANDALONE

Exporte un paper_draft.md existant en Word et PowerPoint, sans relancer la revue.

/sota-export
# ou : /sota-export runs/2026-10-11-mon-sujet
Outputs produits
paper_draft.docx slides_presentation.pptx gen_slides.js

Nécessite Node.js + npm pour pptxgenjs. Les chemins vers apply_theme.js et validate.py sont résolus dynamiquement (aucun chemin absolu codé en dur).

/sota-status
LECTURE SEULE

Diagnostic complet du run actif : fichiers présents sur disque, cohérence des comptages, QualityScore, prochain skill à lancer.

/sota-status
# Affiche : ✅ étapes terminées | ⬜ à faire | ❌ marquées done mais fichier absent
/sota-update
DELTA RUN

Rafraîchit un run existant avec les papiers publiés depuis la date d'extraction initiale, sans relancer tout le pipeline.

/sota-update # demande la fenêtre temporelle delta

Re-exécute ensuite dans l'ordre : Analyst → /sota-quality → /sota-write (mise à jour des clusters) → /sota-review.

5 — Workflow type complet #workflow

Voici la séquence complète d'un run depuis la question de recherche jusqu'au document exporté. Les étapes en orange nécessitent une réponse humaine.

/sota-new "votre sujet de recherche"
Scoper → Strategist (6 APIs) → PDF Retriever → Translator → Curator phase 1
Durée typique : 10–20 min selon le nombre de papiers trouvés
⚠️ Checkpoint A — répondre aux borderlines
Claude présente un tableau des papiers à score ambigu. Répondre : INCLUDE P0012, EXCLUDE P0034
/sota-curate
Finalise le corpus, exécute Analyst + PDF Analyzer (si PDFs disponibles)
/sota-quality
OpenAlex enrichment → QualityScore → Gap Finder → Limits Agent → Figures
Durée typique : 15–30 min (requêtes OpenAlex)
⚠️ Checkpoint B — valider QualityScore + TRL
Répondre PROCEED ou IMPROVE. Si IMPROVE : Claude suggère des améliorations ciblées.
/sota-write
BibTeX → Plan du manuscrit (outline)
⚠️ Checkpoint C — approuver le plan
Claude présente les clusters, le plan des sections, le placement des figures. Approuver ou demander des ajustements.
/sota-write (suite)
Rédaction complète du manuscrit (~8 000 mots)
/sota-review
Revue adversariale + boucle de révision (max 3 itérations) + export auto (.docx + .pptx)
✅ Run terminé
paper_draft.md · paper_draft.docx · slides_presentation.pptx

6 — Résolution de problèmes #troubleshoot

Elsevier retourne HTTP 401

# Vérifier que les variables sont bien exportées (pas juste dans .env)
echo $ELSEVIER_API_KEY   # doit afficher votre clé
export ELSEVIER_API_KEY="..."  # re-exporter si vide

MODULE_NOT_FOUND : pptxgenjs

# Dans le répertoire du run :
npm install pptxgenjs
# Puis re-lancer /sota-export ou /sota-review

apply_theme.js introuvable

# Vérifier que le skill pptx est installé
find $HOME/.claude/skills -name "apply_theme.js" 2>/dev/null
# Si vide : réinstaller le skill pptx depuis Claude Code settings

Doublon détecté après curation

# Vérifier les doublons arXiv dans le CSV
python3 -c "
import pandas as pd
df = pd.read_csv('master_research_data.csv')
dup = df[df.duplicated(subset=['doi'], keep=False) & df['doi'].notna() & df['accepted']==True]
print(dup[['id','title','doi','source_db']])
"

QualityScore trop bas (grade D)

Si QualityScore < 50 :

  1. Vérifier la couverture OpenAlex (flag affiché si < 40%)
  2. Ajouter des requêtes Semantic Scholar ciblées avec S2_API_KEY
  3. Réviser les critères de curation (seuil 4 → 3 pour un domaine émergent)
  4. Utiliser /sota-update après les corrections

gen_slides.js produit des slides avec des données incorrectes

Cause probable : les noms de colonnes du CSV ont changé (ex. après une mise à jour de agent_analyst). Vérifier que CORPUS_N = sum(accepted == True) dans le CSV, et que limits_report.md contient bien une ligne **Mean TRL:**.
