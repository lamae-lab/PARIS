01 Présentation générale

sota-agent est un système de revue systématique automatisée, conçu pour produire des états de l'art conformes au protocole PRISMA 2020 (Preferred Reporting Items for Systematic Reviews and Meta-Analyses). Il orchestre une chaîne de 15 agents spécialisés — chacun défini par un fichier SOUL.md — qui couvrent l'ensemble du processus : de la formulation de la question de recherche jusqu'à l'export en document Word et présentation PowerPoint.

La conception repose sur trois principes : reproductibilité (toutes les requêtes sont loggées, tous les seuils sont explicites), traçabilité (chaque papier retenu peut être retrouvé dans le decision log), et auditabilité (les checkpoints humains empêchent le pipeline de procéder sans validation explicite).

🔍 Couverture bibliographique

7 bases de données interrogées via API : OpenAlex, Semantic Scholar, arXiv, CrossRef, ScienceDirect, IEEE Xplore. Déduplication multi-clé (arXiv ID → DOI → titre).

📊 Analyse quantitative

QualityScore 0–100 (grade A–D) sur 4 dimensions : réseau de citations, bibliométrie, sémantique, processus PRISMA.

📄 Export multi-format

Manuscrit Markdown (~8 000 mots), Word (.docx avec TOC), présentation PowerPoint (11 slides, thème QuantumControl).

⚡ Checkpoints humains

3 arrêts obligatoires : papiers borderline (Checkpoint A), score qualité + TRL (Checkpoint B), plan du manuscrit (Checkpoint C).

04 Concepts clés

Le cadre PICO

Le scoper_agent structure la question de recherche selon le cadre PICO (emprunté à la médecine evidence-based) :

P — Population / Problem

Le système ou domaine ciblé. Ex : systèmes de contrôle quantique.

I — Intervention

La méthode ou approche étudiée. Ex : algorithmes ML/RL.

C — Comparison

L'état de l'art existant. Ex : contrôle optimal classique, PID.

O — Outcome

Les métriques mesurées. Ex : robustesse, fidélité, performance.

Le curator_agent utilise cette grille pour scorer les papiers (0–10) et détecter les blind spots dans l'analyse des limitations.

Déduplication multi-clé

Lors de la curation, chaque entrée de raw_extraction_list.md est comparée aux autres selon trois clés en cascade :

// Priorité 1 : arXiv ID (ex. arXiv:2405.12345)
arXiv ID
→ couvre les preprints capturés depuis arXiv ET OpenAlex

// Priorité 2 : DOI normalisé
DOI
→ couvre les articles publiés dans plusieurs bases

// Priorité 3 : titre normalisé (100 premiers caractères)
titre normalisé
→ fallback pour les entrées sans DOI ni arXiv ID
Leçon du run de test : sans l'arXiv ID comme clé prioritaire, le papier arXiv:2605.26925 avait été indexé deux fois — une fois depuis arXiv, une fois depuis OpenAlex avec un DOI différent. Le doublon P0233/P0362 n'a été détecté qu'au stade de la revue finale.

05 QualityScore — formule et interprétation

Le quality_agent produit un score composite de 0 à 100 sur 4 dimensions, chacune normalisée en [0, 1] avant application des poids.

QS = 100 × [ 0.30 × S_network // réseau de co-citation (OpenAlex) + 0.25 × S_bibliometric // h-index, entropie temporelle, diversité venues + 0.20 × S_semantic // distinctivité clusters, couverture vocabulaire + 0.25 × S_process // taux d'inclusion, balance sources, distribution scores ] // Grade : A (80+) | B (65–79) | C (50–64) | D (< 50) // ⚠️ Si couverture OpenAlex < 40% : S_network × (coverage / 0.40)

S_network (30%)

Construit le graphe de co-citation via OpenAlex. Mesure la modularité (Louvain) et l'alignement avec les clusters thématiques.

S_bibliometric (25%)

H-index du corpus, entropie temporelle, coefficient de Gini des venues, taux de papiers fondateurs (cit. > 50).

S_semantic (20%)

TF-IDF des abstracts : distinctivité inter-clusters, couverture des mots-clés PICO, score de redondance.

S_process (25%)

Taux d'inclusion PRISMA (cible 30–60%), balance entre sources, distribution des scores de pertinence.

06 Matrice TRL (Technology Readiness Level)

Le limits_agent assigne un niveau TRL (1–9) à chaque papier selon des indicateurs observables dans les abstracts et, quand disponible, le texte complet. La matrice révèle la maturité technologique du corpus.

TRL 1–3 — Conceptuel

Pas d'implémentation, résultats analytiques ou de simulation pure. Aucune comparaison à un baseline.

TRL 4–6 — Expérimental

Démo hardware, simulation + expérience partielle, dataset public cité, comparaison à un baseline nommé.

TRL 7–9 — Validé à l'échelle

Déploiement en conditions réelles, benchmark reproductible, résultats vérifiés par un groupe indépendant.
